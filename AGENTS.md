# Agent guidance

This repository contains the source for the Secure-by-Design Handbook, a Docusaurus site. Treat the existing maintainer guides as the source of truth; do not duplicate their full rules here.

## Before making changes

- For changes to handbook content, read [style-guide.md](style-guide.md) and [purpose-and-positioning.md](purpose-and-positioning.md). For blog posts under `blog/`, read the Blog Posts section of the style guide.
- For page placement, URLs, links, or sidebars, read [navigation-structure.md](navigation-structure.md) and check `sidebars.ts` and `docusaurus.config.ts` as needed.
- For entry pages, page titles, and descriptions aimed at search engines, read [entry-page-seo-strategy.md](entry-page-seo-strategy.md).
- For visual or UI changes, read [brand-guidelines.md](brand-guidelines.md).
- For a periodic review of the site, or a change to how reviews run, read [periodic-review.md](periodic-review.md). Past review reports live in `reviews/`.
- Check nearby pages and existing patterns before adding new content or components.

## Content requirements

- Write for product owners, embedded and firmware engineers, compliance and certification leads, and security and DevOps teams at organizations that make, integrate, or operate connected devices.
- Keep guidance vendor-neutral, practical, and evidence-led. Cite the primary source with the clause-level citation format in the style guide, and attribute dates and obligations to the regulation, standard, or authority that sets them.
- Date facts from their source; never add "last checked", "as of", or similar freshness stamps to handbook pages (see the style guide's Dates and freshness section).
- `source-material/` holds local text copies of regulations and standards for checking facts. Cite the official publication, never the copy in this repository.
- Never link to or cite `.ai-helper-files/`; it is gitignored private local drafting material, not a public source.

## Implementation and verification

- Docs live under `docs/` and are served under `/docs/`; blog posts live under `blog/` and are served under `/blog/`. Each top-level docs folder has its own autogenerated sidebar in `sidebars.ts`.
- Diagrams use Mermaid (`mermaid` code blocks). Site search is local and indexes docs only, not the blog.
- Use Node.js 20 or newer and the package scripts rather than ad hoc build commands.
- Before considering a change ready, run `npm run typecheck` and `npm run build`. The build fails on broken links. The [deploy workflow](.github/workflows/deploy.yml) runs the same two commands on every pull request and push to `main`.
- Do not claim checks passed unless they were run and passed. If a check cannot be run, state that clearly.
